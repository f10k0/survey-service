## 6. Ответы на 25 показателей демонстрации (п. 7.6)

Демонстрация - до 5 минут, останавливается на первом неверном ответе.

**1. Проектирование структуры БД.** Сущности: пользователь, опрос,
вопрос, ответ -> таблицы `users`, `surveys`, `questions`, `responses`.
Связи: у опроса много вопросов и ответов, у пользователя много
ответов. `responses` хранит `user_id` и `survey_id`, `questions` -
`survey_id`.

**2. Создание таблиц и связей.** `CREATE TABLE` в `sql/schema.sql`.
`PRIMARY KEY` однозначно определяет запись; `FOREIGN KEY ...
REFERENCES` связывает запись с записью другой таблицы, а при
`PRAGMA foreign_keys = ON` SQLite не даст вставить ответ с
несуществующим `user_id` или `survey_id`.

**3. Создание БД и выполнение схемы.** `sqlite3.connect('data/...')
.close()` создаёт пустой файл; `executescript()` выполняет схему.
Повторный запуск не падает благодаря `CREATE TABLE IF NOT EXISTS`.
Чтобы создать базу заново - удалить файл и повторить команды.

**4. Подключение к БД.** `get_connection()` в `db/database.py`:
`sqlite3.connect(DB_PATH)`, внешние ключи, `row_factory`. Простой запрос:
`SELECT COUNT(*) FROM surveys`. Что используется именно эта база -
смотрим `DB_PATH` (`data/survey_service.sqlite`); если файла нет,
`get_connection()` выдаёт понятную ошибку.

**5. Импорт из JSON.** `db/import_json.py`: читает JSON (`json.load`),
`executemany()` вставляет строки. Преобразования: `is_registered`
(True -> 1), `options` (список -> JSON-строка, `None` -> NULL),
`user_email` -> `user_id`, `id` ответа по порядку записи (если его нет).
Порядок важен из-за внешних ключей: сначала `users` и `surveys`, потом
`responses`.

**6. Проверка результатов импорта.** `SELECT COUNT(*)` по каждой
таблице, сравнение с длиной JSON (users 1, surveys 1, questions 3,
responses 3). Неполный импорт видно по несовпадению количества и по
пустому `JOIN`; ошибка вызывает `rollback()` и исключение.

**7. SELECT.** `SELECT id, name, email FROM users ORDER BY name`
(запрос 1). Если убрать поле из `SELECT`, оно пропадает из результата, и
шаблон не сможет его вывести.

**8. WHERE.** `SELECT ... FROM surveys WHERE topic = 'IT и разработка'`
(запрос 5). Меняем тему - меняется состав результата; в приложении
значение приходит как `?topic=`.

**9. Фильтрация по состоянию.** `WHERE status = 'активен'` (запрос 4):
в результат входят опросы со статусом «активен», остальные (например
«завершён») исключаются.

**10. JOIN.** Запрос 10: `responses JOIN users ON responses.user_id =
users.id JOIN surveys ON responses.survey_id = surveys.id`. Условие
`ON` связывает внешний ключ с первичным; получаем имя пользователя и
название опроса вместо идентификаторов.

**11. Несколько условий.** Запрос 8 (`user_id = 1 AND survey_id = 1`) и
запрос 9: `status = 'активен' AND id NOT IN (подзапрос с user_id = ?)`.
Меняем значение - меняется состав результата.

**12. COUNT().** `SELECT COUNT(*) FROM surveys WHERE status = 'активен'`
(запрос 13). `COUNT(*)` считает строки; если подходящих нет, результат
- 0 (одна строка со значением 0, а не пустой набор).

**13. GROUP BY.** Запрос 18: `GROUP BY surveys.id, surveys.title` формирует
по группе на опрос, `COUNT(responses.id)` считает ответы в каждой
группе. `LEFT JOIN` сохраняет опросы без ответов (получат 0).

**14. HAVING.** Запрос 19: `HAVING COUNT(responses.id) > 1`. `WHERE`
отбирает строки до группировки, `HAVING` - группы после неё (по
результату агрегата). Порог меняется параметром `?min=` на странице
статистики.

**15. Параметризованные запросы.** `fetch_all(SURVEY_SQL, [survey_id])`
- в SQL стоит `?`, значение идёт отдельным списком. Нельзя вставлять
ввод в строку SQL (f-строки): пользователь может изменить смысл запроса
(SQL-инъекция: `' OR '1'='1`). Параметр всегда обрабатывается как
значение.

**16. Получение и обработка результата SQL.** `rows =
fetch_all(sql, params)` внутри view; строки - `sqlite3.Row`, доступ по
имени `row["title"]`; `row_factory = sqlite3.Row` позволяет не зависеть
от порядка столбцов. В `survey_detail` строки `options` дополнительно
превращаются в списки (`json.loads`).

**17. Список объектов.** `/surveys/`: view `surveys()` выполняет
запрос 16 и передаёт `{"surveys": rows}` в `survey_list.html`, где
`{% for survey in surveys %}`.

**18. Отфильтрованные записи.** `/surveys/active/` (WHERE по статусу) и
`/surveys/?topic=Спорт` (WHERE по теме): SQL определяет, какие записи
попадут в контекст, шаблон только выводит их.

**19. Связанные данные.** `/responses/` и `/responses/<id>/`: JOIN трёх
таблиц даёт ответ, имя пользователя и название опроса в одной строке.

**20. Поиск по параметрам пользователя.** `/surveys/available/?user=1`:
`request.GET.get("user")` -> проверка `isdecimal()` -> запрос
`USER_SQL` -> `AVAILABLE_SURVEYS_SQL` с параметрами
`[ACTIVE_STATUS, user_id]`.

**21. Статистика.** `/responses/statistics/`: view выполняет запросы
13-15, 18, 19, 21 и кладёт результаты в контекст (`totals`,
`per_survey`, `popular`, `last_responses`); шаблон их выводит.

**22. Передача результатов в шаблон.** Имя в контексте должно
совпасть с шаблоном: если view передаёт `{"surveys": ...}`, а шаблон
использует `{% for item in items %}`, страница будет пустой без ошибки
(Django подставляет пустую строку). Исправление - привести имена к
одному.

**23. Пустые результаты.** Пустой результат - корректный ответ SQL
(нет подходящих строк); страница показывает ветку `{% empty %}`
(«Доступных опросов нет»). Ошибка SQL - исключение (например
`no such table`) и страница 500.

**24. Диагностика ошибок SQL.** Типичные случаи: неверное имя поля
(`no such column`), опечатка в таблице (`no such table`), забытое
условие `ON` в `JOIN` (лишние строки), `INNER JOIN` вместо `LEFT JOIN`
(пропали опросы без ответов), условие `is_cancelled/status` в `WHERE`
вместо `ON` у `LEFT JOIN` (то же). Проверяем запрос отдельно в SQLite,
затем в view.

**25. Сквозная обработка запроса.** Браузер -> URLconf -> view ->
`request.GET` -> `fetch_all(SQL, [params])` -> `sqlite3` -> SQLite ->
строки `Row` -> `context` -> шаблон -> HTML -> ответ. Некорректный
результат ищем по этапам: параметр (`request.GET`), SQL (в CLI), данные
в таблицах, имя в контексте, шаблон.

## 7. Ответы на контрольные вопросы (п. 8)

### Базы данных и реляционная модель

1. **База данных** - организованное хранилище данных для их
   сохранения, поиска и обработки.
2. **БД и СУБД:** БД - сами данные; СУБД - программа, которая создаёт,
   хранит, изменяет данные и отвечает на запросы (здесь SQLite).
3. **Реляционная БД** - данные хранятся в таблицах, связанных
   ключами.
4. **Таблица** - набор данных об однотипных объектах; **запись
   (строка)** - один объект; **поле (столбец)** - свойство объекта.
5. **Типы SQLite:** INTEGER, REAL, TEXT, BLOB, NULL.
6. **Первичный ключ** однозначно идентифицирует запись.
7. **Внешний ключ** ссылается на запись другой таблицы и задаёт связь.

### Выборка и фильтрация данных

8. **SQL** - язык запросов к реляционным БД.
9. **SQL и Python:** SQL декларативный (описывает, какие данные
   нужны), Python императивный (описывает шаги).
10. **SELECT** выбирает столбцы, **FROM** - таблицу.
11. **WHERE** фильтрует строки.
12. **`=`** равно; **`<>` и `!=`** - не равно (в SQLite оба работают).
13. **IN** - значение из списка; **BETWEEN** - в диапазоне
    (включительно); **LIKE** - по шаблону (`%`, `_`). В SQLite `LIKE`
    нечувствителен к регистру только для латиницы.
14. **AND/OR/NOT** - логическое И/ИЛИ/НЕ; скобками задаётся порядок.
15. **NULL** проверяется `IS NULL` / `IS NOT NULL`, а не `= NULL`.
16. **DISTINCT** убирает повторы (запрос 2: список тем).

### Сортировка, агрегация и группировка

17. **ORDER BY** сортирует результат.
18. **ASC** по возрастанию (по умолчанию), **DESC** по убыванию.
19. **LIMIT** ограничивает число записей, **OFFSET** пропускает
    первые N (запрос 21: `LIMIT 5`).
20. Без `ORDER BY` порядок строк не гарантирован, поэтому страницы
    выборки могут «прыгать».
21. **Агрегатная функция** вычисляет одно значение по набору строк.
22. **`COUNT(*)`** считает все строки, **`COUNT(column)`** - только
    не-NULL значения.
23. **MIN, MAX, AVG, SUM** - минимум, максимум, среднее, сумма
    (запрос 15: возраст пользователей).
24. **GROUP BY** объединяет строки с одинаковым значением поля в
    группы.
25. **WHERE** фильтрует строки до группировки, **HAVING** - группы
    после.
26. Порядок: FROM/JOIN -> WHERE -> GROUP BY -> HAVING -> SELECT ->
    ORDER BY -> LIMIT/OFFSET.

### Работа с SQLite из Python

27. **`sqlite3`** - стандартная библиотека для работы с SQLite.
28. Этапы: `connect()` -> `cursor()` -> `execute()` -> `fetchall()` ->
    обработка -> `close()`.
29. **cursor** выполняет запросы и хранит результат; у соединения
    есть ярлык `conn.execute()`, который создаёт курсор сам.
30. **`commit()`** сохраняет изменения транзакции (после INSERT);
    `rollback()` отменяет.
31. F-строки позволяют пользователю изменить смысл запроса
    (SQL-инъекция) и ломаются на кавычках.
32. **Параметризованный запрос:** в SQL стоят `?`, значения передаются
    отдельно; библиотека подставляет их безопасно.
33. **`executemany()`** выполняет одну команду для списка наборов
    значений (импорт нескольких записей за раз).
34. **Файловая база** хранится на диске и сохраняется между
    запусками; **`:memory:`** живёт в оперативной памяти и исчезает при
    закрытии соединения.
35. **`:memory:`** удобна для быстрых тестов и экспериментов, где
    данные не нужно сохранять.
36. **Результаты SELECT:** `cursor.fetchall()`, `fetchone()`,
    `fetchmany()` или итерация по курсору.

### Индивидуальный проект

37. Раньше: загрузка JSON целиком в объекты Python, поиск и подсчёт
    циклами в коде (консоль), чтение и вывод через view и шаблоны (веб).
38. Преимущества БД: фильтрация, поиск, сортировка и подсчёт
    выполняются средствами SQL без чтения всех данных; контроль
    целостности (ключи, `NOT NULL`, `UNIQUE`); связи между таблицами;
    транзакции; удобное масштабирование и несколько пользователей.
39. Таблицы: `users`, `surveys`, `questions`, `responses`; связи:
    `questions.survey_id -> surveys.id`, `responses.user_id -> users.id`,
    `responses.survey_id -> surveys.id`.
40. Основные запросы: список и фильтр опросов, активные опросы, опросы
    без прохождения пользователем (`NOT IN`), ответы с JOIN, статистика
    (`COUNT`, `GROUP BY`, `HAVING`), последние ответы (`LIMIT`).
