## 1. Что сделано в ПР5 (кратко)

1. Проект ПР3 сохранён и продолжен: консоль (`main.py`), классы
   `models/`, JSON-хранилище `storage.py`, тесты.
2. Создан Django-проект `survey_service` и три приложения.
3. Приложения зарегистрированы в `INSTALLED_APPS`.
4. Маршрутизация двух уровней: `survey_service/urls.py` +
   `urls.py` каждого приложения (`include()`).
5. View-функции возвращают `HttpResponse` с HTML-страницей.
6. Единый каркас страницы — `page(title, content)` в
   `homepage/views.py`, Bootstrap 5.3 через CDN.
7. Динамические URL: `<int:survey_id>`, `<int:response_id>`.
8. Обработка 404: для объекта (в view) и для адреса (`handler404`).
9. Данные ПР3 выводятся на страницах через `load_*()` и
   `find_*_by_id()`.
10. Обновлён README, добавлены тесты `tests/test_web.py`.

Отступления от методички (и почему):

* Старые модули ПР2 `users.py`, `surveys.py`, `responses.py` в корне
  перенесены в `legacy_pr2/`: имя модуля `surveys.py` совпадает с
  именем приложения, и `startapp surveys` завершается ошибкой
  «conflicts with the name of an existing Python module».
  Эти модули нигде не импортировались (используется пакет `models/`).
* В `Response` добавлено поле `id` (в методичке у `Booking` оно уже
  было): без него нельзя построить `/responses/<id>/`. В старом
  `responses.json` поля `id` нет — при загрузке оно назначается по
  порядку записи.
* Пути к JSON строятся от `BASE_DIR` (`settings.SURVEYS_FILE` и т. д.),
  а не относительно текущей папки: сервер работает из любой директории.
* Пользовательский текст в HTML экранируется `escape()` (защита от
  внедрения HTML/скриптов).
* Вместо `DEBUG = False` в итоговом коде оставлено `DEBUG = True`
  (методичка: после проверки 404 вернуть `True`).

## 6. Ответы на 25 показателей демонстрации (п. 7.5)

Демонстрация — до 5 минут, останавливается на первом неверном ответе,
поэтому порядок важен. Ниже — готовые ответы с привязкой к коду.

**1. Структура проекта Django.** Пакет `survey_service/`:
`settings.py` — настройки (INSTALLED_APPS, MIDDLEWARE, TEMPLATES,
DATABASES, LANGUAGE_CODE, TIME_ZONE, DEBUG, ALLOWED_HOSTS, пути к
JSON); корневой `urls.py` — маршруты верхнего уровня (`admin/`, `""`,
`surveys/`, `responses/`) и `handler404`. Остальное: `asgi.py`,
`wsgi.py` — точки входа серверов, `__init__.py` — признак пакета.

**2. Проверка и запуск.** `manage.py` — точка входа команд управления
(устанавливает `DJANGO_SETTINGS_MODULE`). `python manage.py check` —
проверка конфигурации без запуска; `python manage.py runserver` —
запуск development-сервера; `migrate` — применение миграций.

**3. Регистрация приложений.** В `settings.py` список `INSTALLED_APPS`
содержит `"homepage"`, `"surveys"`, `"responses"`. Если приложение
создано, но не зарегистрировано, Django его не «видит»: не подхватит
его модели и миграции, админку, шаблоны из `templates/` приложения,
конфигурацию `apps.py`. (Импорт `include("surveys.urls")` по пути
пакета может ещё работать, но полноценной частью проекта приложение не
станет.)

**4. Приложения проекта.** `homepage` — главная, `page()`, 404;
`surveys` — опросы (`/surveys/`, `/surveys/<id>/`); `responses` —
ответы (`/responses/`, `/responses/<id>/`). Отдельного приложения для
пользователей нет: в Django уже есть встроенная модель `User`
(`django.contrib.auth`), своё приложение `user` конфликтовало бы с ним;
класс `User` из ПР3 (`models/users.py`) остаётся для консоли, работа с
пользователями будет в следующих темах.

**5. Режим отладки.** Перед `DEBUG = False` нужно заполнить
`ALLOWED_HOSTS` (у нас `["localhost", "127.0.0.1"]`) — иначе Django
ответит 400 на любой запрос. При `DEBUG = True` ошибки показываются
технической страницей со списком маршрутов, `handler404` не
используется; при `False` показывается наша страница 404, детали
ошибок скрыты, встроенный сервер не раздаёт статические файлы.

**6. Маршрутизация `/surveys/999/`.** Корневой `urls.py`:
`path("surveys/", include("surveys.urls"))` — отрезает префикс
`surveys/`; остаток `999/` Django ищет в `surveys/urls.py`:
`path("<int:survey_id>/", views.survey_detail)` → вызывается
`survey_detail(request, survey_id=999)`. `include()` разделяет адрес
между проектом и приложением: префикс описан в корне, остальная часть —
в приложении.

**7. Связь маршрута и view.** `path("<int:survey_id>/",
views.survey_detail, name="survey_detail")`: значение из `<int:…>`
передаётся в view одноимённым параметром `survey_id`. Если переименовать
view-функцию — в `urls.py` меняем только второй аргумент `path()`, URL
продолжит работать. `name=` — имя маршрута: по нему в следующих ПР
строятся ссылки (`reverse()`, `{% url %}`), не зависящие от жёстко
заданного адреса.

**8. Конвертер `<int:…>`.** `/surveys/abc/` не соответствует шаблону
(`int` — только цифры), маршрут не найден → Django сразу отдаёт 404 и
view не вызывается. `/surveys/999/` соответствует шаблону, view
вызывается, но опроса с id 999 нет — 404 формирует сама view.

**9. Обработка запроса главной страницы.** Браузер: `GET / HTTP/1.1` →
Django берёт `ROOT_URLCONF = "survey_service.urls"` →
`path("", include("homepage.urls"))` → `homepage/urls.py`:
`path("", views.index)` → вызывается `index(request)` → формирует HTML
через `page("Сервис опросов", content)` → возвращает
`HttpResponse` (200, `text/html`) → браузер рисует страницу.

**10. Запрос и представление.** Django создаёт объект `HttpRequest` и
передаёт первым аргументом в view; view возвращает `HttpResponse`
(в коде — `return HttpResponse(page(...))`). Если вернуть обычную
строку, Django выдаст ошибку («view didn't return an HttpResponse
object. It returned a str instead») и код 500.

**11. Формирование HTML главной.** В `index()` строка `content` —
HTML-фрагмент (заголовок, абзацы, кнопки). Она передаётся вторым
аргументом в `page(title, content)`, где вставляется в
`<main class="container">{content}</main>` внутри полного документа.
`HttpResponse` отправляет документ браузеру. Если передать в `page()`
другой текст — изменится содержимое страницы (заголовок вкладки — при
изменении `title`).

**12. Назначение `page()`.** Единый каркас всех страниц, чтобы не
копировать его в каждую view: `<!DOCTYPE>`, `<html lang>`, `<head>`
(charset, viewport, `<title>`, подключение Bootstrap), `<nav>` с
навигацией, `<main class="container">`. Из конкретной view передаются
`title` (заголовок вкладки) и `content` (содержимое страницы).

**13. Повторное использование.** Общая часть (каркас, навигация,
Bootstrap) — в `page()`; конкретная (заголовки, карточки, списки) — в
`content` каждой view. Одна функция обслуживает все страницы:
`page("Сервис опросов", …)`, `page(survey.title, …)`,
`page(f"Ответ №{response.id}", …)`.

**14. Изменение содержимого.** Меняем первый аргумент `page()` в нужной
view, например в `survey_detail`: `page(survey.title, content)` →
`page("Другой заголовок", content)`; каркас не трогаем. В браузере
изменится текст вкладки.

**15. Bootstrap.** В `<head>`, внутри `page()`:
`<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/css/bootstrap.min.css">`.
Без этой строки страницы останутся без оформления (чистый HTML).
Используемые классы: `container`, `nav`, `nav-link`, `display-4`,
`lead`, `btn btn-primary/secondary/outline-secondary`, `list-group`,
`list-group-item`, `card`, `card-body`, `card-title`, `card-text`,
`badge bg-success/bg-secondary`, `text-danger`, `me-2`, `mt-3`.

**16. Загрузка и поиск данных.** `load_surveys(filename)` в
`storage.py` возвращает `list[Survey]`. `find_survey_by_id(surveys,
survey_id)` в `models/surveys.py` возвращает `Survey` или `None`. В
`survey_detail()`: `surveys_list = load_surveys(settings.SURVEYS_FILE)`,
`survey = find_survey_by_id(surveys_list, survey_id)`.

**17. Путь данных.** `data/surveys.json` → `_load_json()` (`json.load`
→ список словарей) → `Survey.from_data(item)` для каждого элемента
(внутри `Question.from_data()` для вопросов) → список объектов
`Survey` → `find_survey_by_id()` → объект `Survey` в
`survey_detail()`. Для ответа цепочка длиннее: `load_surveys()`,
`load_users()`, затем `load_responses()` связывает объекты
`Response ↔ User/Survey`, затем `find_response_by_id()`.

**18. Объект в представлении.** `Survey` создан на уровне предметной
области (`models/surveys.py`), view его не описывает заново. Функция
поиска возвращает объект; `survey_detail()` читает `survey.id`,
`survey.title`, `survey.topic`, `survey.creation_date`,
`survey.questions` (каждый `question.text`, `question.options`,
`question.is_open()`), вызывает `survey.is_active()`. Значения
подставляются в f-строку `content` и попадают в HTML.

**19. Атрибуты → HTML.** Например, `{escape(survey.title)}` в
`<h5 class="card-title">`. Изменим `title` в `data/surveys.json`,
обновим страницу `/surveys/1/` — новое название отобразится (данные
читаются при каждом запросе).

**20. Типы данных.** `id` — `int`; `title`, `topic`, `status`,
`creation_date` (ISO-строка) — `str`; `questions` —
`list[Question]`; `options` — `list[str]` или `None` (открытый
вопрос); у `Response`: `id` — `int`, `user` — `User`, `survey` —
`Survey`, `question`/`answer` — `str`; у `User`: `age` — `int`,
`is_registered` — `bool`. Число в URL конвертер `<int:…>` превращает в
`int` до вызова view.

**21. Обработка 404.** При отсутствии маршрута Django ищет
`handler404` в корневом `urls.py`:
`handler404 = "homepage.views.page_not_found"`. Функция принимает
`request` и `exception` (на странице не показывается) и возвращает
`HttpResponse(page("404 - страница не найдена", content),
status=404)`. Работает при `DEBUG = False`; настраивается один раз для
всех приложений (в `urls.py` приложения игнорируется).

**22. Нет маршрута vs нет ресурса.** Нет маршрута (`/nonexistent/`,
`/surveys/abc/`) — Django не находит view и сам вызывает `handler404`.
Маршрут найден, но объекта нет (`/surveys/999/`) — view выполнилась и
вернула 404 сама (`HttpResponse(..., status=404)`). `handler404`
вызывается при отсутствии маршрута и при `raise Http404` из view; наш
явный `return HttpResponse(status=404)` его не вызывает (поэтому там
своя страница «Опрос не найден»).

**23. Ветвление в представлении.** В `survey_detail()`:
`if survey is None:` → страница «Опрос не найден» и 404; иначе —
карточка опроса. Если убрать проверку и сразу обратиться к
`survey.title`, для id 999 будет `AttributeError: 'NoneType' object has
no attribute 'title'` → ошибка 500.

**24. Отсутствующий объект.** `find_survey_by_id()` возвращает `None`,
если объекта нет. Обращение к атрибуту `None` даст `AttributeError`
(500 вместо понятного 404), поэтому результат поиска проверяется до
использования.

**25. Изменение HTTP-статуса.** В ветке `if survey is None:` меняем
`status=404` на `status=403`. Проверка: DevTools браузера (вкладка
Network, столбец Status), `curl -i http://127.0.0.1:8000/surveys/999/`
или тест `client.get(...).status_code`. Смысл: 404 — ресурс не найден;
403 — ресурс распознан, но доступ к нему запрещён.

## 7. Ответы на контрольные вопросы (п. 8)

### Django и веб-разработка

1. **Веб-приложение** — программа, доступная через браузер/HTTP-клиент;
   пользователь отправляет HTTP-запросы, программа возвращает ответы.
2. **Фреймворк** — готовая структура и набор инструментов, которые сами
   управляют ходом программы и вызывают код разработчика.
3. **Django** — веб-фреймворк для Python: маршрутизация, обработка
   запросов, шаблоны, ORM, формы, аутентификация, админка, тесты.
4. **Фреймворк и библиотека.** Библиотеку вызывает наш код; фреймворк
   сам вызывает наш код (view, обработчики) по своим правилам.
5. **Django-проект** — общая конфигурация системы: настройки,
   маршрутизация верхнего уровня, точки запуска (`survey_service/`).
6. **Django-приложение** — функциональная часть, реализующая одну
   область (`surveys`, `responses`, `homepage`).
7. **Проект и приложение.** Проект — одна конфигурация на весь сайт;
   приложений в проекте несколько, каждое отвечает за свою область.
8. **`manage.py`** — запуск команд управления проектом (`runserver`,
   `check`, `migrate`, `startapp`).
9. **`settings.py`** — настройки проекта: приложения, middleware,
   шаблоны, БД, язык, часовой пояс, режим отладки.
10. **`urls.py`** — соответствие адресов и обработчиков (маршрутизация).
11. **`views.py`** — view-функции: принимают запрос и возвращают ответ.
12. **Development-сервер** — встроенный сервер для разработки
    (`runserver`, `http://127.0.0.1:8000/`); не для рабочей эксплуатации.

### HTTP

13. **HTTP** — протокол передачи гипертекста, стандарт обмена
    «запрос — ответ» между клиентом и сервером.
14. **HTTP-запрос** — сообщение клиента серверу: метод, адрес,
    заголовки, (иногда) тело.
15. **HTTP-ответ** — сообщение сервера: код статуса, заголовки, тело
    (например HTML-страница).
16. **Части запроса:** стартовая строка (метод, адрес, версия,
    `GET /surveys/ HTTP/1.1`), заголовки (`Host`, `User-Agent`,
    `Accept`), тело.
17. **Части ответа:** стартовая строка (версия, код статуса
    `HTTP/1.1 200 OK`), заголовки (`Content-Type`, `Content-Length`),
    тело.
18. **URL** — адрес ресурса (`http://127.0.0.1:8000/surveys/1/`).
19. **Маршрут** — правило соответствия шаблона адреса и обработчика
    (`path("<int:survey_id>/", views.survey_detail)`).
20. **После обращения к URL:** запрос → корневой `urls.py` →
    `urls.py` приложения → view → `HttpResponse` → браузер.
21. **HTTP-метод** — тип действия: `GET` (получить), `POST`
    (отправить данные) и др.
22. **GET и POST.** `GET` запрашивает данные, параметры в адресе, тело
    обычно пустое; `POST` отправляет данные на сервер в теле запроса
    (формы). В ПР5 используется только `GET`.

### URL и view

23. **`path()`** — описывает маршрут: шаблон адреса, view-функция,
    (необязательно) имя маршрута.
24. **Конвертер пути** — часть шаблона (`<int:…>`, `<str:…>`,
    `<slug:…>`), проверяющая сегмент и преобразующая его к типу.
25. **`<int:id>`** — принимает целое неотрицательное число и передаёт
    его во view как `int` в параметр `id`.
26. **View-функция** — обычная функция Python, обрабатывающая запрос и
    возвращающая ответ.
27. **Параметр view** — первым всегда `request` (`HttpRequest`); далее
    параметры из шаблона адреса (`survey_id`).
28. **Возвращает** объект ответа `HttpResponse` (или его подкласс).
29. **`HttpResponse`** — класс HTTP-ответа: принимает содержимое
    (строку) и `status` (код статуса).
30. **Параметр из URL в view:** переменная в угловых скобках в
    `path()` → одноимённый аргумент функции.
31. **Имена маршрутов** (`name=`) позволяют строить ссылки по имени, а
    не по жёсткому адресу — адрес можно менять без правки ссылок.
32. **Отделение маршрутизации от логики:** проще менять адреса и
    логику независимо, поддерживать проект, переиспользовать код.

### HTML, CSS и Bootstrap

33. **HTML** — язык разметки гипертекста, описывает структуру
    веб-страницы.
34. **HTML-документ** — страница, которую браузер отображает пользователю.
35. **Части документа:** `head` (служебное: кодировка, заголовок
    вкладки, стили) и `body` (содержимое).
36. **HTML-элемент** — тег (или пара тегов) с содержимым и атрибутами:
    `<a href="/">Главная</a>`.
37. **CSS** — язык описания внешнего вида: цвета, размеры, отступы.
38. **CSS-селекторы** определяют, к каким элементам применяются
    стили (по тегу, классу, id).
39. **Наследование стилей** — свойства родительских элементов
    переходят к вложенным (если не переопределены).
40. **Bootstrap** — CSS-фреймворк с готовыми компонентами (навбар,
    кнопки, карточки, списки) и адаптивной сеткой.
41. **Для чего:** быстрая вёрстка через готовые классы, без написания
    CSS с нуля.
42. **Преимущества CSS-фреймворка:** скорость, единый стиль,
    адаптивность, готовые компоненты, проверенный кроссбраузерный код.

### Индивидуальный проект

43. **Предметная область:** сервис проведения опросов — опросы,
    вопросы, пользователи, ответы.
44. **Страницы:** главная, список опросов, страница опроса, список
    ответов, страница ответа, страница 404.
45. **URL:** `/`, `/surveys/`, `/surveys/<id>/`, `/responses/`,
    `/responses/<id>/`.
46. **View-функции:** `index`, `page_not_found` (+ `page`),
    `surveys`, `survey_detail`, `responses`, `response_detail`.
47. **Путь запроса:** браузер → URL → `survey_service/urls.py` →
    `include()` → `urls.py` приложения → view → загрузка данных
    (`load_*`) → `page()` → `HttpResponse` → HTML в браузере.
48. **Перенесено из ПР3:** классы `Question`, `Survey`, `User`,
    `Response`, функции `load_*`, `find_survey_by_id`,
    `get_survey_statistics`, `is_active()`; JSON-хранилище, тесты и
    консоль продолжают работать.
49. **Почему ещё нет ORM:** ПР5 посвящена основам (HTTP, URL, view,
    HTML); данные пока берутся из JSON средствами ПР3; ORM и БД
    изучаются в следующих работах.
50. **После подключения БД:** классы станут Django-моделями,
    JSON-хранилище заменит БД (SQL через ORM), `models.py` приложений
    заполнятся, появятся миграции и админка.
51. **Данные для страниц:** JSON-файлы `data/surveys.json`,
    `data/users.json`, `data/responses.json`.
52. **На следующих ПР:** шаблоны Django (`render()`, `base.html`,
    наследование), статические файлы, Django ORM и БД, формы,
    создание/редактирование объектов, аутентификация, API, Docker,
    CI/CD.

## 8. Быстрые модификации «на лету» (могут попросить на защите)

* **Изменить заголовок страницы:** первый аргумент `page(...)` во view.
* **Сменить код 404 на 403:** `status=403` в ветке `if … is None:`.
* **Показать другой текст на главной:** строка `content` в
  `homepage/views.py::index`.
* **Проверить 404-страницу:** `DEBUG = False` →
  `/nonexistent/` → вернуть `DEBUG = True`.
* **Добавить пункт в навигацию:** строка `<a class="nav-link" …>` в
  `page()`.
* **Новый URL:** `path()` в `urls.py` приложения + view-функция в
  `views.py`.
