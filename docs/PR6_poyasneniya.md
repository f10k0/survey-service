## 1. Что сделано в ПР6

1. `settings.py`: в `TEMPLATES` добавлено `"DIRS": [BASE_DIR / "templates"]`.
2. Шаблоны уровня проекта: `templates/base.html`,
   `templates/includes/navigation.html`, `templates/404.html`.
3. Шаблоны приложений: `homepage/templates/homepage/index.html`;
   `surveys/templates/surveys/{survey_list,survey_detail}.html` и
   `includes/{survey_card,survey_status}.html`;
   `responses/templates/responses/{response_list,response_detail}.html`.
4. Все view переведены на `render(request, "...html", context)`.
   Функция `page()` удалена; HTML в Python не формируется.
5. В `urls.py` каждого приложения добавлен `app_name`, маршруты
   названы `list` и `detail`; ссылки строятся через `{% url %}`.
6. Статика `homepage/static/homepage/`: `css/style.css`, `js/main.js`,
   `img/logo.png`; подключена в `base.html` через `{% load static %}`.
7. Фильтры: `length`, `default`, `join`.
8. Ветвление `{% if %}`, циклы `{% for %}`/`{% empty %}`.
9. Обновлён README (п. 5.12), добавлены тесты `tests/test_templates.py`.

Что отличается от методички и почему:

* Статус опроса (аналог статуса бронирования) вынесен в
  `survey_status.html` и используется и в карточке списка, и на
  странице опроса - как требует п. 5.8.2.
* Условие в шаблоне - `{% if survey.is_active %}` (метод класса
  вызывается без скобок), а не сравнение строки со статусом.
* У `Response` нет «статуса», поэтому статус-include относится к
  опросу.
* Фильтр `date` не применён: дата создания хранится строкой (ISO), а
  `date` работает только с объектами `date`/`datetime`. Это указано в README.
* Пути к JSON берутся из `settings` (от `BASE_DIR`), а не
  относительные `"data/..."`.
* Автоэкранирование шаблонов Django заменило ручной `escape()` из ПР5.
* В Bootstrap-ссылке URL записан в одну строку: перенос строки внутри
  `href` ломает адрес (в PDF он разбит только для вёрстки).

## 6. Ответы на 25 показателей демонстрации (п. 7.6)

Демонстрация - до 5 минут, останавливается на первом неверном ответе.

**1. Наследование шаблонов.** `base.html` - общий каркас, дочерний
(например `survey_list.html`) начинается с `{% extends "base.html" %}` -
Django берёт базовый шаблон и подставляет в его блоки содержимое
дочернего. Изменить заголовок: поменять текст в
`{% block title %}Опросы - Сервис опросов{% endblock %}`, во вкладке
браузера он будет отличаться от базового «Сервис опросов».

**2. Переопределение блоков.** В базовом шаблоне объявлены
`{% block title %}` и `{% block content %}`; дочерний шаблон
переопределяет их одноимёнными блоками. Меняем содержимое блока
`content` (например заголовок `<h1>`) - Django при рендеринге
подставляет блок дочернего шаблона вместо блока базового, поэтому
изменение видно на странице.

**3. Передача контекста.** `render(request, "surveys/survey_list.html",
{"surveys": surveys_list})`; в шаблоне `{% for survey in surveys %}`.
Если переименовать ключ (`"items"`), в шаблоне `surveys` станет
неопределённой: цикл не выполнится (сработает `{% empty %}`),
`{{ surveys|length }}` выведет 0.

**4. Атрибуты объектов.** `{{ survey.title }}`, `{{ survey.topic }}`,
`{{ response.user.name }}`. Если написать несуществующий атрибут
(`{{ survey.titel }}`), Django не выбросит исключение, а выведет пустую
строку.

**5. Отсутствующие переменные.** Переменной нет в контексте -
выводится пустая строка (по умолчанию `string_if_invalid = ""`).
Исключение не вызывается, чтобы ошибка данных не ломала всю страницу;
но из-за этого опечатку найти труднее: страница открывается, а данных
нет. Искать - сверять имена ключей контекста и шаблона.

**6. Автоэкранирование.** `{{ survey.title }}` с текстом
`<b>x</b>` отобразится как текст `<b>x</b>` (в HTML -
`&lt;b&gt;x&lt;/b&gt;`). Отключение (`|safe`,
`{% autoescape off %}`) опасно, если текст вводит пользователь:
возможно внедрение скриптов (XSS). Это проверяет тест
`test_autoescape_in_templates`.

**7. Обработка коллекций.** `{% for survey in surveys %}` в
`survey_list.html`. Если передать пустой список (в `data/surveys.json`
`[]`), сработает `{% empty %}` - «Опросов пока нет.». Для списка
ответов - «Ответов пока нет.».

**8. Условное отображение.** `{% if survey.is_active %}` в
`survey_status.html`: активный - зелёный бейдж, иначе серый. Чтобы
показать изменение, в `data/surveys.json` поменять `"status"` на
`"завершён"` - бейдж сменится на серый.

**9. Использование фильтров.** `{{ surveys|length }}` - количество
опросов, `{{ survey.title|default:"Без названия" }}`,
`{{ question.options|join:", " }}`. Фильтр меняет только вид значения
при выводе; можно дописать `{{ survey.title|upper }}` или
`|truncatechars:30`.

**10. Фильтр `default`.** Подставляет значение, если переменная пустая
или отсутствует: при `"title": ""` в карточке будет «Без названия».
Влияет на отображение пустых значений, не меняя данные.

**11. Повторное использование шаблонов.** `{% include %}`: навигация
(`includes/navigation.html` в `base.html`), карточка
(`survey_card.html` в списке), статус (`survey_status.html` в карточке
и на странице опроса). Изменив один файл (например слово «Подробнее»),
видим изменение во всех местах, где он подключён.

**12. Данные внутри включаемого шаблона.** Карточка использует
`survey` из внешнего цикла `{% for survey in surveys %}`: include
получает контекст внешнего шаблона. Если переименовать переменную цикла
(`{% for s in surveys %}`), а в карточке останется `survey`, данные
исчезнут (пустые строки).

**13. Динамические URL.** `{% url 'surveys:detail' survey.id %}` →
`/surveys/1/`. Меняется передаваемый id - меняется адрес (для id=2 -
`/surveys/2/`). Параметр попадает в `<int:survey_id>`.

**14. Пространства имён.** `app_name = "surveys"` в `surveys/urls.py`
вместе с `name="detail"` даёт имя `surveys:detail`. Если изменить
`app_name` или `name`, нужно обновить все `{% url %}` в шаблонах
(`navigation.html`, `survey_card.html`, `response_detail.html`),
иначе будет ошибка `NoReverseMatch`.

**15. Конвертер параметров.** `<int:survey_id>` принимает только цифры.
`/surveys/abc/` - маршрут не совпал, view не вызывается, сразу 404;
`/surveys/999/` - маршрут совпал, view вызвана, объекта нет.

**16. Объекты не найдены.** `find_survey_by_id()` возвращает `None`;
view передаёт `survey=None` и `status=404 if survey is None else 200`;
шаблон показывает «Опрос не найден». Для демонстрации - открыть
`/surveys/999/`.

**17. Ошибки маршрутизации и поиска объекта.** `/nonexistent/` -
нет маршрута: срабатывает `handler404` (при `DEBUG=False`) и
`404.html`. `/surveys/999/` - маршрут есть, view выполнилась, не
найден объект: 404 формирует сама view через `render(..., status=404)`.

**18. Ошибки поиска шаблона.** `render()` обращается к шаблону по
имени. Неверное имя файла - `TemplateDoesNotExist` (при DEBUG
перечислены каталоги, где Django искал). Синтаксическая ошибка внутри
найденного шаблона - `TemplateSyntaxError` с номером строки. Различать
по типу исключения и тексту ошибки.

**19. Поиск ошибок в шаблонах.** Типичная ошибка - незакрытый тег
(`{% if %}` без `{% endif %}`, `{% for %}` без `{% endfor %}`):
`TemplateSyntaxError: Unclosed tag`. Страница не формируется, пока тег
не закрыт. Исправление - добавить парный закрывающий тег.

**20. Статические ресурсы.** `{% load static %}` в начале `base.html`,
затем `{% static 'homepage/css/style.css' %}`, `.../js/main.js`,
`.../img/logo.png`. Если путь неверный, ресурс не загрузится (в DevTools
→ Network будет 404); проверить файл: `python manage.py findstatic
homepage/img/logo.png`.

**21. Изменение стилей.** Класс `survey-card` в `survey_card.html` связан
с правилом `.survey-card` в `style.css`. Например, в `style.css`
изменить `border-left: 5px solid #0d6efd;` на другой цвет - обновить
страницу (Ctrl+F5), цвет полоски карточки изменится.

**22. Диагностика JavaScript.** `main.js` ищет элемент
`id="current-year"` в подвале `base.html` и записывает текущий год. Если
файл не загрузился - в DevTools → Network ошибка 404, года нет; если
загрузился, но есть ошибка в скрипте - в DevTools → Console видно
сообщение с номером строки.

**23. Организация шаблонов приложений.** Шаблон приложения лежит в
`<app>/templates/<app>/...`, например
`surveys/templates/surveys/survey_list.html`, и подключается именем
`"surveys/survey_list.html"`. Повторение имени приложения в пути
исключает конфликты одноимённых файлов в разных приложениях, так как
Django собирает шаблоны всех приложений в один список путей.

**24. Согласованность представления и шаблона.** View передаёт
`{"survey": survey, "stats": stats}`; шаблон использует `survey.title`
и `stats.items`. Если в view поменять ключ `"survey"` на `"item"`,
страница станет пустой/«Опрос не найден»; исправить - привести имена в
view и шаблоне к одному виду.

**25. Путь запроса `/surveys/1/`.** Браузер → `survey_service/urls.py`:
`path("surveys/", include("surveys.urls"))` → `surveys/urls.py`:
`path("<int:survey_id>/", views.survey_detail, name="detail")` →
`survey_detail(request, survey_id=1)`: `load_surveys()` (JSON → объекты),
`find_survey_by_id()`, `get_survey_statistics()` → context →
`render()` → `surveys/survey_detail.html` (наследует `base.html`) →
HTML → HTTP-ответ 200. Если опрос с таким id есть, поиск вернёт объект
`Survey`; ошибка могла бы возникнуть только на этапе загрузки JSON или в
шаблоне, если неверно имя переменной/тег.

## 7. Ответы на контрольные вопросы (п. 8)

### Шаблоны Django и контекст

1. **Для чего шаблоны:** отделить представление (HTML) от Python-кода;
   шаблон отвечает за отображение данных.
2. **Почему HTML в Python неудобен:** смешиваются обработка запроса,
   данные, разметка и оформление; трудно читать, повторять, менять и
   поддерживать; нет наследования и переиспользования.
3. **`render()`:** принимает `request`, имя шаблона и контекст,
   подставляет данные в шаблон и возвращает `HttpResponse`
   (дополнительно можно указать `status`).
4. **Контекст:** словарь с данными, доступными в шаблоне по ключам.
5. **Передать список объектов:** `context = {"surveys": surveys_list}`
   и `render(request, "...html", context)`; в шаблоне
   `{% for survey in surveys %}`.
6. **`{{ ... }}`:** вывод значения переменной или атрибута
   (`{{ survey.title }}`).
7. **`if` и `for`:** `{% if %}` показывает блок по условию, `{% for %}`
   перебирает коллекцию.
8. **`{% empty %}`:** выводит запасное содержимое, если коллекция пуста.

### Наследование и включение

9. **Базовый шаблон:** общий каркас всех страниц (`base.html`) с
   блоками для изменяемых частей.
10. **`extends` и `block`:** `{% extends %}` указывает родителя,
    `{% block %}` задаёт заменяемые участки.
11. **`include`:** вставляет в шаблон фрагмент из другого файла
    (с текущим контекстом).
12. **Когда выносить в include:** если фрагмент повторяется (карточка,
    статус, навигация) или логически самостоятелен.

### Именованные URL и пространства имён

13. **`name` в `path()`:** имя маршрута, по которому строится ссылка.
14. **`app_name`:** пространство имён приложения в его `urls.py`.
15. **Зачем namespace:** одноимённые маршруты в разных приложениях
    (`list`, `detail`) не конфликтуют: `surveys:list`, `responses:list`.
16. **`/surveys/` и `{% url "surveys:list" %}`:** первое - жёстко
    заданный адрес, сломается при смене маршрута; второе строится из
    `urls.py` и остаётся рабочим при изменении адреса.

### Фильтры

17. **Фильтры:** изменяют представление значения в шаблоне
    (`|length`, `|default`, `|join`, `|date`).
18. **`length`:** возвращает число элементов (длину строки/списка).
19. **`date`:** форматирует объект даты/времени, например
    `{{ d|date:"d.m.Y" }}`. В проекте даты хранятся строками, поэтому
    фильтр не применён.

### Статические файлы

20. **`{% load static %}`:** подключает библиотеку тегов, без неё
    `{% static %}` не работает.
21. **Где хранить статику:** в каталоге `static/<app>/` приложения
    (у нас `homepage/static/homepage/`).
22. **CSS:** `<link rel="stylesheet" href="{% static 'homepage/css/style.css' %}">`.
23. **Изображение:** `<img src="{% static 'homepage/img/logo.png' %}" alt="...">`.
24. **JavaScript:** `<script src="{% static 'homepage/js/main.js' %}"></script>`.
25. **Почему не только Bootstrap:** он даёт базовую вёрстку, но
    собственный CSS задаёт индивидуальное оформление проекта
    (`.survey-card`, `.survey-status`); Bootstrap его не заменяет.

### Архитектура и индивидуальный проект

26. **View и шаблон:** view - получить данные, найти объект, подготовить
    контекст, вызвать `render()`; шаблон - отобразить данные (циклы,
    условия, форматирование).
27. **Бизнес-логика не в шаблонах:** шаблон для представления;
    логику в нём трудно тестировать и переиспользовать, она размывается
    между слоями.
28. **Почему JSON, а не ORM:** ORM и база данных изучаются в следующих
    работах; ПР6 перестраивает слой представления, источник данных не
    меняется.
29. **Отличие от ПР5:** в ПР5 JSON → объекты → view → HTML-строка в
    Python → `HttpResponse`; в ПР6 JSON → объекты → view → context →
    шаблон → HTML → ответ.
30. **Зачем отказ от `page()`:** HTML выносится из Python в шаблоны,
    повторяющаяся структура - в `base.html` и `include`, view остаются
    короткими и отвечают только за данные.
